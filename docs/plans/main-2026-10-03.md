# Phase 2 Plan: Discovery → Connection, Metrics & Automated Intake

Date: 2026-10-03
Branch: main
Author: CS Club Lead (with DeepSeek as senior staff engineer / architectural mentor)

---

## Context & Constraints

- The app is a **discovery + connection** layer: connect high-school students with local nonprofits. Shift tracking and hour verification are owned by the student + school board (HDSB), **not** this app.
- Hard rule: **no student PII, nothing requiring school-board IT approval.** The app stores no names, emails, student IDs, or DOB.
- University-application metrics must be **audit-proof, verifiable, and free of inflated/artificial data**. Anti-spam, rate-limiting, and deduplication exist to prove bot traffic was filtered.
- A **human vetting step is non-negotiable** for safety (students are minors; an unvetted listing could be fraudulent or dangerous).

## Confirmed Decisions

1. **Identity:** stateless anonymous `anonymousId` (privacy-preserving daily session hash, stored in localStorage). No accounts, no device tokens.
2. **Intake:** `IntakeAdapter` interface + one generic RSS/JSON adapter (Dependency Inversion Principle). No vendor lock-in.
3. **Admin:** `ADMIN_KEY` env var, checked via middleware (pages) and headers (API routes). Timing-safe comparison.
4. **Rate limits:** 3/min per `anonymousId` on POST/mutations; 20/min per `ipHash`. Reads more lenient (60/min per IP).
5. **Hours:** collected and stored, **always labeled self-reported** in reporting. Data kept, never silently dropped.

## Schema Additions

### Modified: `Opportunity`
- `status` String — `pending | approved | rejected`
- `sourceId` Int? — FK to `OpportunitySource`
- `sourceUrl` String?

### New: `OpportunitySource`
- `id`, `name`, `baseUrl`, `type` (`rss|json`), `consentStatus`, `enabled`, `lastScrapedAt`, `createdAt`

### New: `ApplyEvent`
- `id`, `opportunityId`, `anonymousId`, `requestId`, `ipHash`, `userAgent`, `createdAt`
- `UNIQUE(anonymousId, opportunityId)` — one apply per opportunity per user

### New: `HourLog`
- `id`, `opportunityId`, `anonymousId`, `hours`, `note?`, `createdAt`

### New: `BlockedAttempt`
- `id`, `anonymousId?`, `ipHash`, `reason`, `createdAt`

### New: `ReviewAction`
- `id`, `opportunityId`, `action` (`approve|reject`), `note?`, `createdAt`

All event tables are **append-only** (no update/delete paths). This is the audit trail.

## Intake & Vetting Flow

- `lib/intake/types.ts` — `IntakeOpportunity` + `IntakeAdapter` interface.
- `lib/intake/genericFeed.ts` — one adapter handling RSS (`rss-parser`) and JSON feeds via `fetch`.
- `lib/intake/registry.ts` — maps `OpportunitySource.type` → adapter factory.
- Cron route (`GET /api/cron/scrape`, guarded by `CRON_SECRET` via Vercel Cron) runs **only** sources with `consentStatus: "ok"` + `enabled`.
- Upsert performs automated checks: valid HTTPS URL, required fields, category allowlist, `hours > 0` → malformed items auto-`rejected`.
- Everything else lands as `pending` → a human approves/rejects in `/admin`.

### Consent & Safety Rules

- Only scrape/republish from sources that **permit republication** (RSS/public aggregator feeds). `consentStatus` recorded per source.
- `sourceUrl` on every opportunity provides provenance (who we scraped it from).
- Automated checks protect against scams, expired listings, phishing links, and dangerous placements.
- Human approval in the queue is the safety gate. Nothing `pending`/`rejected` appears publicly.

## Rate Limiting & Dedup Design

- `lib/security.ts`:
  - `rateLimit({ key, scope, limit, windowMs })` — DB-based sliding-window count (consistent across serverless instances; no extra infra).
  - `hashIp(ip)` — one-way hash before storage (no raw IPs persisted).
  - `timingSafeEqual` comparison for `ADMIN_KEY` / `CRON_SECRET`.
- Apply flow:
  - Check idempotency via `requestId` + `UNIQUE(anonymousId, opportunityId)`.
  - On limit hit → insert `BlockedAttempt` (with reason) and return `429`. **Log, don't drop silently.**

## Metrics (audit-safe, derivable from logs)

- **Active users:** `COUNT(DISTINCT anonymousId)` from `ApplyEvent`
- **Apply events:** `COUNT(ApplyEvent)`
- **Spam filtered:** `COUNT(BlockedAttempt)` — proves bot/duplicate filtering
- **Self-reported hours:** `SUM(HourLog.hours)` — always labeled self-reported, never in the "verified" set

## Lean Scope (implemented 2026-10-04)

Decided: keep the two non-negotiable pillars (safety vetting, metric integrity), cut all optional abstraction.

**Deferred (note — not built yet):**

| Deferred | Why |
|---|---|
| `HourLog` / self-reported hours | Hours are HDSB's responsibility; no storage until a real UI needs it |
| `OpportunitySource` CRUD API + sources admin UI | Start with a single hardcoded source config |
| `ReviewAction` audit table | Use `status` + `reviewedAt` on `Opportunity` instead |
| Generic JSON intake adapter | Ship RSS only; add JSON when a real source needs it |
| Intake adapter `registry` abstraction | Single `sources.ts` config object |
| Admin dashboard pages / middleware | Admin APIs use header auth only; mentees build UI later |
| `POST /api/events/hours` | Follows from `HourLog` deferral |

**What IS built (lean Phase 2):**
- `Opportunity` + `status` (`pending|approved|rejected`), `sourceId`, `sourceUrl`, `reviewedAt`
- New tables: `OpportunitySource`, `ApplyEvent`, `BlockedAttempt`
- `lib/security.ts` — in-memory rate limiting, IP hashing, timing-safe key check
- `POST /api/events/apply` — rate-limited (3/min user, 20/min IP), deduped, append-only log
- `GET /api/admin/queue` + `POST /api/admin/review` — ADMIN_KEY header auth
- `lib/intake/*` — `IntakeOpportunity`, `IntakeSourceAdapter`, one RSS adapter, `sources.ts`
- `GET /api/cron/scrape` — CRON_SECRET guarded, upserts as `pending`, skips malformed
- `GET /api/metrics` — active users, apply events, blocked attempts
- Public list/API filtered to `status: "approved"`; POST creates as `pending`
